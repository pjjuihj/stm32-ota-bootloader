# STM32 OTA Bootloader 开发日志

---

## 项目介绍

### 背景

在嵌入式开发中，固件升级是一个常见需求。传统的升级方式需要拆卸设备、连接调试器，既不方便也不安全。OTA（Over-The-Air）升级技术允许通过无线或有线方式远程更新固件，大大提高了维护效率。

本项目基于 STM32F407 微控制器，实现了一个完整的 OTA 升级系统，支持通过 UART 串口进行固件升级。

### 项目目标

1. **实现 OTA 升级功能** - 通过串口远程更新固件
2. **支持 A/B 分区** - 升级失败可回滚，保证设备安全
3. **提供 PC 工具** - 图形化界面，操作简便
4. **保证可靠性** - CRC 校验，错误恢复机制

### 技术栈

| 层级 | 技术 |
|------|------|
| **硬件** | STM32F407VETx, OLED SSD1306, CH340 USB转串口 |
| **固件** | C语言, STM32 HAL库, Keil MDK-ARM |
| **工具** | Python, Tkinter, pyserial |
| **协议** | 自定义 UART 命令协议 |

### 适用场景

- 工业设备远程维护
- 消费电子产品固件升级
- IoT 设备空中升级
- 嵌入式系统现场调试

## 开发历程

### 第一天：基础搭建

**目标：** 搭建 Bootloader 基础框架

**完成内容：**
- Flash 布局设计（A/B 分区）
- UART 通信协议
- 基本命令解析

**遇到的问题：**
1. **PA0 按键电平配置错误**
   - 假设：按下为低电平（接地）
   - 实际：按下为高电平（接 VCC）
   - 教训：不要假设硬件配置，先测量

2. **向量表地址问题**
   - APP 编译地址与实际运行地址不匹配
   - 解决：使用统一编译地址 + VTOR 重定位

---

### 第二天：OTA 协议实现

**目标：** 实现完整的 OTA 升级流程

**完成内容：**
- HEX 文件解析
- 固件数据传输
- CRC32 校验
- A/B 分区切换

**遇到的问题：**
1. **UART 缓冲区溢出**
   - 现象：数据传输过程中丢失字节
   - 原因：Flash 写入期间 UART 中断被禁用
   - 解决：添加 4096 字节环形缓冲区

2. **CRC 校验失败**
   - 现象：传输完成后 CRC 不匹配
   - 原因：数据在传输过程中损坏
   - 解决：增加块间延时，确保 Flash 写入完成

---

### 第三天：OLED 显示集成

**目标：** 添加 OLED 状态显示

**完成内容：**
- OLED 初始化
- 进度条显示
- 状态信息显示

**遇到的问题：**
1. **OLED 初始化卡死**
   - 现象：I2C 通信失败导致初始化挂起
   - 解决：添加 500ms 超时保护

2. **进度条不更新**
   - 现象：OTA 进度条不动
   - 原因：没有在数据处理中调用更新函数
   - 解决：在 `Bootloader_HandleData()` 中添加进度更新

---

### 第四天：PC 上位机工具

**目标：** 开发 PC 端 OTA 工具

**完成内容：**
- Python GUI 界面
- 串口通信
- HEX 文件解析
- OTA 升级流程

**遇到的问题：**
1. **GUI 工具串口通信失败**
   - 现象：最简工具正常，GUI 工具失败
   - 原因：CustomTkinter 干扰串口通信
   - 解决：使用标准 tkinter，或关闭 GUI 串口后运行最简工具

2. **波特率兼容性**
   - 现象：高波特率（460800）通信不稳定
   - 原因：CH340 芯片在高波特率下不稳定
   - 解决：使用 115200 波特率

---

### 第五天：优化与完善

**目标：** 优化性能和用户体验

**完成内容：**
- 传输速度优化
- 错误处理改进
- 人机交互优化

**遇到的问题：**
1. **OTA 速度慢**
   - 现象：12KB 固件需要 95 秒

   - 原因：GUI 工具发送速度太快
   - 解决：使用与最简工具相同的发送逻辑

## 核心功能

### 1. OTA 升级流程

```
1. 用户发送 ota_enter → 设置 Boot 魔数 → 复位
2. Bootloader 检测魔数 → 进入 OTA 模式
3. 发送 ota_start <size> → 擦除目标分区
4. 发送 ota_data × N → 写入固件数据
5. 发送 ota_end <crc> → CRC 校验 → 切换分区
6. 跳转到新 APP
```

### 2. A/B 分区切换

```
初始状态：Active = Partition A
├─ 第一次 OTA → 写入 B → 切换到 B
├─ 第二次 OTA → 写入 A → 切换到 A
└─ 第三次 OTA → 写入 B → 切换到 B
```

### 3. 错误恢复

```
OTA 失败场景：
├─ CRC 校验失败 → 丢弃固件，继续运行旧 APP
├─ 搬运失败 → Partition B 保持不变
└─ 新 APP 运行崩溃 → 回滚标志 → 恢复旧 APP
```

## 关键代码

### 1. Flash 操作

```c
// 擦除 Sector
HAL_FLASH_Unlock();
FLASH_EraseInitTypeDef erase_init;
erase_init.TypeErase = FLASH_TYPEERASE_SECTORS;
erase_init.Sector = FLASH_SECTOR_3;
erase_init.NbSectors = 3;
HAL_FLASHEx_Erase(&erase_init, &sector_error);
HAL_FLASH_Lock();

// 写入数据
HAL_FLASH_Unlock();
for (uint32_t i = 0; i < len; i += 4) {
    uint32_t word = data[i] | (data[i+1] << 8) | 
                    (data[i+2] << 16) | (data[i+3] << 24);
    HAL_FLASH_Program(FLASH_TYPEPROGRAM_WORD, addr + i, word);
}
HAL_FLASH_Lock();
```

### 2. UART 中断接收

```c
// 4096 字节环形缓冲区
#define UART_RX_BUF_SIZE 4096
static volatile uint8_t uart_rx_buf[UART_RX_BUF_SIZE];
static volatile uint16_t uart_rx_head = 0;
static volatile uint16_t uart_rx_tail = 0;

// 中断回调
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart) {
    uint16_t next_head = (uart_rx_head + 1) % UART_RX_BUF_SIZE;
    if (next_head != uart_rx_tail) {
        uart_rx_buf[uart_rx_head] = uart_rx_byte;
        uart_rx_head = next_head;
    }
    HAL_UART_Receive_IT(&huart1, &uart_rx_byte, 1);
}
```

### 3. CRC32 校验

```c
uint32_t Bootloader_CalculateCRC(const uint8_t *data, uint32_t len) {
    uint32_t crc = 0xFFFFFFFF;
    for (uint32_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (int j = 0; j < 8; j++) {
            if (crc & 1) {
                crc = (crc >> 1) ^ 0xEDB88320;
            } else {
                crc >>= 1;
            }
        }
    }
    return crc ^ 0xFFFFFFFF;
}
```

## 遇到的问题与解决方案

### 问题 1：PA0 按键电平配置错误

**现象：** 按下 PA0 按键，APP 没有反应

**原因：** 假设按下为低电平，实际为高电平

**解决：** 先用万用表测量，确认电平逻辑

**教训：** 嵌入式开发中，硬件配置是基础，不要假设

---

### 问题 2：UART 缓冲区溢出

**现象：** 数据传输过程中丢失字节，CRC 校验失败

**原因：** Flash 写入期间 UART 中断被禁用，新数据无法接收

**解决：** 添加 4096 字节环形缓冲区，在中断中接收数据

**教训：** 嵌入式系统处理速度有限，需要缓冲机制

---

### 问题 3：GUI 工具串口通信失败

**现象：** 最简工具正常，GUI 工具失败

**原因：** CustomTkinter 框架干扰串口通信

**解决：** 使用标准 tkinter，或关闭 GUI 串口后运行最简工具

**教训：** GUI 框架可能干扰底层通信，保持简单

---

### 问题 4：OTA 速度慢

**现象：** 12KB 固件需要 95 秒

**原因：** 块大小太小（64字节），延时太长（0.5秒）

**解决：** 增加块大小到 128 字节，减少延时到 0.2 秒

**结果：** 速度从 130 字节/秒提升到 580 字节/秒

## 经验教训

### 1. 硬件配置要先确认

```
错误做法：假设 PA0 是低电平有效
正确做法：先用万用表测量，确认电平逻辑
教训：嵌入式开发中，硬件配置是基础
```

### 2. Flash 操作要谨慎

```
错误做法：频繁擦写 Flash
正确做法：减少擦写次数，使用 A/B 分区
教训：Flash 有寿命限制（~10000 次）
```

### 3. 串口通信要稳定

```
错误做法：发送速度太快
正确做法：增加延时，确保处理完成
教训：嵌入式系统处理速度有限
```

### 4. GUI 工具要简单

```
错误做法：使用复杂的 GUI 框架
正确做法：使用标准 tkinter，保持简单
教训：GUI 框架可能干扰底层通信
```
